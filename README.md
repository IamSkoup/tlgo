# Savanna Freedom Online

Fan-made browser game with a static Three.js client, an authoritative Node.js/WebSocket game server, and a real Supabase Postgres/Auth backend. The new Supabase project is **Savanna Freedom Online**, project ID `zxndmytaxmuguxjwmaij`. It is independent of the Kapani website and its data. The original standalone game is preserved under `client/legacy.html` and does not grant online currency.

**Project status (7 November 2026).** This is a playable networked *foundation*, **not** the complete premium production game described in `docs/ORIGINAL_BRIEF.md`. Account creation, nickname uniqueness, a 700×700 landscape, 16 types of animal, simultaneous players, named NPC encounters with dialogue, combat, movement, stamina, server-validated resources and Claws, three individual quests, an actual two-stage cooperative patrol for 2–4 players, friends, clans, invitation-only rooms, protected purchases, natural coat color choices, private messages, session/local/clan chat, report submission and persistent player positions have implementation paths. The client includes a mixer with 26 locally hosted CC0 samples, pursuit/combat audio and detailed settings. Server-side player collision with the map's deterministic trees, rocks and major landmarks is enforced. High-detail character models, skeletal animations, free flight for eagles, an expansive cinematic campaign, item/equipment gameplay, an in-world mission editor, complex NPC AI, in-game moderation dashboards, sophisticated vertical/slope collision and broad mobile/browser QA remain unfinished. The standalone legacy mode retains its original mechanisms and separate saves.

## What must be connected

The Supabase schema **has already been created** in the project above. All six SQL migrations are saved in `supabase/migrations/` and have been applied in order to that project; do not reapply them there. The browser already has the project URL and *public* publishable key in `client/config.js`. A separate Node server needs a **privileged key** from **Supabase Dashboard → Project Settings → API Keys**. Never paste this key into the browser or commit it into Git.

In the Supabase Dashboard, open **Authentication → URL Configuration**. Set `Site URL` to the eventual web-client URL and add its complete URL (and local `http://localhost:8080` while developing) to the redirect URL allowlist. This is necessary for email confirmation and password reset. Set sensible Auth security rules for a public project, including confirmation email and Auth rate limits; for production use a properly configured SMTP provider. Auth-related redirect URLs are documented at https://supabase.com/docs/guides/auth/redirect-urls.

The game server is **not deployed by pushing to GitHub**. GitHub Pages cannot host persistent WebSocket connections. The included `render.yaml` lets you create a Render Blueprint web service called `tlgo-game`, using `server/`. In [Render Blueprints](https://dashboard.render.com/select-repo?type=blueprint), connect `IamSkoup/tlgo`, supply `SUPABASE_SERVICE_ROLE_KEY` in Render's secret field (never in Git), and deploy. After provisioning, check `https://tlgo-game.onrender.com/health`. If Render assigns a different service hostname, edit the production `gameWebSocketUrl` in `client/config.js` accordingly. The preconfigured `ALLOWED_ORIGINS` is `https://iamskoup.github.io` for the Pages project site.

The `.github/workflows/pages.yml` action verifies the server tests, then publishes **only** `client/` at `https://iamskoup.github.io/tlgo/` on pushes to `main`. In Settings → Pages, select **GitHub Actions** as the build and deployment source. The static interface and preserved old offline game can load before the separate WebSocket server is running; online play requires it. A free Render instance can spin down when idle, disconnecting online players; always-on hosting is recommended for real multiplayer use.

## Local launch

Use Node.js 22 or later. In `server/`, copy `.env.example` to `.env`, then edit it to provide `SUPABASE_URL`, the *private* `SUPABASE_SERVICE_ROLE_KEY`, `PORT=8787`, and `ALLOWED_ORIGINS=http://localhost:8080`. There is no secret in the delivered archive.

From inside `server/`, run `npm ci` then `npm run start:env`. From inside `client/` in a second terminal, run `python3 -m http.server 8080`. Browse to `http://localhost:8080`. The supplied `client/config.js` chooses `ws://localhost:8787/game` on localhost and the expected `wss://tlgo-game.onrender.com/game` on GitHub Pages. Confirm the actual hostname after Render deploys. An HTTPS page cannot connect to `ws://`.

For Docker, build from `server/` with `docker build -t savanna-game .` and run the container with `docker run --env-file .env -p 8787:8787 savanna-game`. Do not place `.env` in the image. The container exposes `/health` for uptime checks and `/metrics` for non-sensitive room and connection counts. Keep the game server at one replica for now. Multi-replica play needs shared room routing and state; separate room processes are not yet coordinated.

## Controls and features

On desktop, WASD moves, Shift sprints, Space jumps, E gathers, R talks to a nearby named character, F triggers the species ability, left mouse button attacks a nearby target, held right mouse button rotates the camera, M opens the map, Enter focuses chat and Escape opens or closes the menu. The HUD includes phone controls. Players can invite one another into a cooperative patrol, gather two herb bundles with teammates nearby and defeat two hostile hyenas. The group bonus is granted once per account per UTC calendar day; the group itself currently exists in the game process and will not survive a restart. Switching species and changing cosmetics while already in a session is allowed only from a safe location. Both PvP participants must opt in, and safe areas never allow attacks between players. All server wallet rewards use immutable ledger keys and SQL transaction functions; the browser cannot submit arbitrary amounts.

Six species are free choices at initial character creation. Other starter species cost 120 Claws each after creation. Upgrades cost 45 Claws times the next rank. Premium species start at 320 Claws. Eight natural coat colors are available for 65 Claws per change, while the initial coat is free. Friend-to-friend direct messages and clan history are stored in the database; proximity chat is intentionally ephemeral. In the new game, animal characteristics are server-owned and earnings cannot be imported from old local saves.

The audio system contains terrain-dependent footsteps for grass, sand, rock and wet soil; impact, bite, landing, jump and reward sounds; looping wind and savanna ambience; water proximity; occasional storm thunder; and adaptive music for pursuit, combat and some active quests. Individual audio categories, graphics presets, render resolution, dynamic shadows, FPS cap, camera distance and sensitivity, mouse inversion, plus audio mute/dynamic music are adjustable and saved locally in the browser. Browsers require the first click/gesture before playing sound. Sources and license details are in `docs/AUDIO_CREDITS.md`.

## Tests and measured limits

Run `npm test` in `server/`. At delivery there are **28 passing Node tests**. These cover movement, forged reward/teleport intents, resource idempotency, combat/safe zones, authoritative terrain collision, room isolation, quest continuation, social invitations, wanted decay, idle movement expiration, NPC dialogue, cooperative patrol rewards, cosmetic spending, friend-only direct messaging, clan privacy, sanction filtering and audio settings. Additional tests open **real WebSocket connections** for two independently authenticated fake identities, join the same session, receive snapshots, exchange chat messages and reject a forged reward; origin/auth refusal is also verified. Client-asset checks confirm that page dependencies, dynamic element IDs and all 26 Ogg files exist. These are simulated test identities, **not** real browser users connected to the live Supabase Auth service. All six SQL migrations were applied to the live database and Supabase Security Advisor returned **zero notices** on the most recent scan. We cannot claim a complete two-real-account or cross-device browser end-to-end test until the production WSS host and backend private key are configured.

Run `npm run bench` for a synthetic 18-player server-core load. On the current test runtime, simulating 10 seconds with the world snapshot rate at 10 Hz yielded **0.338 ms p95 simulation work per 50 ms tick** and **4.293 MiB outgoing snapshot payload** over 10 simulated seconds, about **25.76 MiB per minute**. This excludes TLS/WebSocket overhead, real Supabase round trips, browsers' 3D rendering and Internet latency. The model suggests approximately **1.5 GiB of outbound server traffic per hour** if 18 densely clustered players stay online continuously. Bandwidth, not movement calculation, is an early scaling concern. Client FPS on a real phone and two-client Internet latency have not yet been reliably measured.

For a small hobby population, Supabase's current Free plan includes a 500 MB database, 50,000 monthly active users and 5 GB egress, subject to additional limits and inactivity pausing. The continuous Node game server needs separate hosting; pricing depends on the host. The **database project's free tier is not a free always-on WebSocket server**. Verify plans at https://supabase.com/pricing before committing to a hosting provider. The game is expected to exceed 5 GB egress if players frequently pull files or persist large chat histories, and a standalone VPS may have its own bandwidth ceilings.

## Security and operational notes

Use the exact environment variable names documented in `.env.example`. Privileged Supabase RPCs are explicitly denied to browser roles. Auth access tokens are checked on game-server connection and active sanctions are enforced; one active socket per user is intended; inputs are rate limited, normalized and bounded. Player money, damage, reputation, quests and purchases are server-owned. An admin-only command-line utility `npm run moderate -- reports`, `npm run moderate -- ban USER_UUID HOURS REASON` and `npm run moderate -- unban USER_UUID` can inspect the latest 50 reports and issue/revoke timed access bans from the secured server. It needs the same private environment file as the game server and writes audit entries. Static trees, rocks and major scenery colliders are now generated from the same seed as the browser world and movement is resolved server-side; advanced slopes, jump arcs and moving obstacles need further work. Natural coat colors are reflected in the 3D animal meshes, but there is no detailed fur/model customization pipeline. For public release, set up backups, uptime alerts and real-device/real-user tests.

## File layout

`client/` contains the static site, source code, samples and the preserved old game. `server/` contains the authoritative simulation, persistence adapter, WebSocket entry point, test fixtures and Docker image. `supabase/migrations/` contains ordered SQL schema migrations already applied to the new project. `docs/` contains the original full request and source credits. Public keys in `config.js` may be committed; secrets must not.
